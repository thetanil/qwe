## What

Two review findings about the teardown e2e cases:
- **Timing:** `operator_cancel` and `parallel_cancel` send their signal after a fixed 0.7 s, which ticket 08 asks to avoid.
- **Weak check:** `grace_then_sigkill` only proves the shell died; an immediate SIGKILL would pass it too.

With the lifecycle trace from ticket 18, both can be made exact.

## Acceptance criteria

- [ ] The e2e harness can send qwe's signal when a named file appears in the work dir, as well as after a fixed delay. `e2e: tests/e2e/harness_selftest_signal_on_file/`
- [ ] `operator_cancel` and `parallel_cancel` signal on a marker file that their steps create, not after a delay. `e2e: tests/e2e/operator_cancel/`, `e2e: tests/e2e/parallel_cancel/`
- [ ] `grace_then_sigkill` checks the job's trace against a golden: step timeout, then `step-stopping`, then `grace-expired`, then `step-killing`, then `group-empty`. That golden would fail if SIGKILL came first. `e2e: tests/e2e/grace_then_sigkill/`
- [ ] No teardown e2e case depends on a fixed delay to pass. `manual: grep the case dirs' signal files for a bare delay; there should be none left`

## Agent Brief

**Category:** enhancement
**Summary:** Remove fixed delays from the teardown e2e cases, and have the grace-period case check the lifecycle trace.

**Current behavior:**
The harness's `signal` file takes `<seconds> <SIGNAME>` and sleeps before signalling. Two cases rely on 0.7 s being long enough for their steps to start. `grace_then_sigkill` checks only that no process is left.

**Desired behavior:**
The harness can wait for a file to appear (with a generous upper bound that fails the test if exceeded) before signalling. The cancel cases wait for their steps' marker files. The grace case compares that job's trace lines, with times normalised, against a golden.

**Key interfaces:**
- The harness's `signal` file format gains a form that waits for a file. The header comment of the harness script documents it.

**Acceptance criteria:** the checklist in this ticket's Acceptance criteria section.

**Out of scope:**
- New lifecycle behaviour. This ticket changes tests and the harness only.
