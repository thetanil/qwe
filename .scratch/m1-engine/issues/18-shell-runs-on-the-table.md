# 18: The engine runs on the lifecycle table

Status: resolved
Category: enhancement
Type: task
Blocked by: 17, 21

## What

Replace the workflow event loop's outcome flags with the lifecycle table from ticket 17. The loop becomes a thin shell with three jobs: turn fds and signals into events, filter out stale step-scoped events by step index, and carry out the actions the table returns. The scheduler stops changing job states and sends `needs-met`, `needs-failed` and `slot-granted` instead. This ticket also adds the lifecycle trace, `qwe run --debug`, and the `engine-error` reason (see the M1 spec: CLI, Run artifacts, Behaviour 2).

Until ticket 19 lands, the shell sends `group-empty` straight after the leader is reaped, which is the same behaviour as today. The table's straggler states are therefore in place, but not yet exercised end to end.

## Agent Brief

**Category:** enhancement
**Summary:** Drive the workflow event loop from the ADR-0010 lifecycle table, and add the lifecycle trace, `--debug` and `engine-error`.

**Current behavior:**
The event loop decides outcomes with the flags `failed`, `torn`, `tearing`, `step_trigger` and `step_live`, spread over its step and job functions. The scheduler moves jobs `pending → ready | skipped` itself. There is no trace and no `--debug`. A step that fails to spawn is recorded as `failed`/`exit-code`, and a job whose log cannot be opened gets the undocumented reason `internal` and leaks its ring and timer.

**Desired behavior:**
The loop's only decisions are "which event is this?" and "is it stale?". Every state change comes from a lookup in the table, and every action the lookup returns is carried out. The scheduler emits events. Loading jobs from the workflow (including refusing unimplemented keys) moves out of the event-loop file into its own unit. `result.json`, the exit codes and the terminal output are unchanged.

**Key interfaces:**
- The run context holds a trace sink. It writes lines in the format of the spec's "Run artifacts" section and flushes before an abort.
- `qwe run` accepts `--debug`, as in the spec's CLI section.
- The scheduler's pass returns events for jobs rather than changing their states.
- The step-scoped events carry the step index.

**Acceptance criteria:** the checklist in this ticket's Acceptance criteria section.

**Out of scope:**
- The subreaper and a real `group-empty` (ticket 19).
- Signalling from a marker file in the e2e harness, and a trace golden for `grace_then_sigkill` (ticket 20).
- Any change to `result.json`'s shape.

### Resolution

- `workflow.c` is now the shell: `dispatch_one` is the only place `job->state` changes (stale filter, lookup, trace line, actions). `job_send` adds what a job is owed while it waits for nothing (the cursor's `next-step`/`no-more-steps`, a `start-failed` after a failed action). Job loading moved to `jobs.c`/`jobs.h`; the trace to `trace.c`/`trace.h`. `job_state.*` and its tests are deleted.
- The scheduler (`sched.c`) reads states and returns events. A pass returns `needs-*` events if any job has them, else `slot-granted` for ready jobs, so a newly ready job keeps its index priority. The caller passes until it returns 0.
- epoll tags are packed `(job, kind, step)` in `data.u64`, so a late event of an ended step keeps the step it was opened for and the stale filter can drop it. A job timeout is stale once the job has ended (`qwe_lc_event_is_stale`).
- An operator cancel is sent once to every job (`cancel_told`), so a finished job gets one ignore line and a job in `between-steps` is cancelled by the table.
- `--debug` adds an `event` line for every event as it arrives, before the table. Without it the trace has every transition, ignore and stale line.
- `engine-error`: a failed spawn (`pipe`/`fork`) or timer is `start-failed` in `step-running(-coe)`; a failed log/ring/timer is `start-failed` in `between-steps`. The trace line carries `op=<op> errno=<NAME>`. The old leak of the ring and timer on that path is gone (`job_release`).
- Harness: `lifecycle.trace` times are normalised to `TIME`. A `ulimit` file (bash, because dash has no `ulimit -u`) runs qwe under a limit. `engine_error_spawn` uses `-u 1`, so the fork really fails; it needs a non-root user, because root ignores `RLIMIT_NPROC`.
- Between this ticket and 19, `group-empty` is sent straight after the leader is reaped, so a step's stragglers now get one SIGTERM at leader exit (the table's `settling-*-term`) but are not waited for.
